# v0.15.0 - GPU instancing

- **Tag** `v0.15.0`
- **Date** 2026-11-22
- **Release** [v0.15.0](https://github.com/animu-sphere/usd-gltf-plugins/releases/tag/v0.15.0)

The importer reads `EXT_mesh_gpu_instancing` as a `UsdGeomPointInstancer` named `Instances` below the
node, whose only prototype is the node's mesh. Each instance's translation, rotation and scale apply
before the node's transform, as glTF composes them. No Khronos sample file now ignores the extension.
See the [changelog](../../CHANGELOG.md#0150---2026-11-22) and the
[GPU instancing decision](../adr/0043-gpu-instancing.md).

## Compatibility and limits

- Packages target the pinned OpenStrata `cy2026` / `usd` runtimes on Windows x86-64, Linux x86-64
  and macOS arm64 with OpenUSD 26.08 and Python 3.13.
- The path of an instanced node's mesh changes from `Node_{n}/Mesh_{m}` to
  `Node_{n}/Instances/Mesh_{m}`. See the [scene conventions](../design/SCENE_CONVENTIONS.md#gpu-instancing).
- Rotations are authored as float `orientationsf`. A consumer that reads only the half-precision
  `orientations` sees no rotation, and one that traverses prims without instancer support sees the
  prototype once at the node.
- Custom `_` instance attributes, and skins or morph targets on an instanced node, fail with a
  diagnostic. On a node without a mesh, the extension is ignored with a warning.
- The archived `KHR_materials_pbrSpecularGlossiness` and the unratified `KHR_meshopt_compression`
  are still rejected.

## Verification observed

On Windows x86-64 with OpenUSD 26.08, both SimpleInstancing files open, their instancer agrees with
values decoded from the glTF, and they draw their 125 cubes through MaterialX and UsdPreviewSurface in
Storm. Of the 339 sample files, 334 open and 5 are rejected, each for a cause it has; 311 have their
meaning verified. See the [sample check](../reference/CAPABILITY_MATRIX.md#sample-assets). The
[display check](../reference/CAPABILITY_MATRIX.md#display-checks) passed 853 comparisons, including
instances below a node with a non-uniform scale.

The [release gate](../roadmap/README.md#release-gate) repeats the checks at the commit to be
tagged. The GitHub release provides package pins and checksums.
