# v0.2.0 - wider static scene support

- **Tag:** `v0.2.0`
- **Date:** 2026-11-09
- **Release:** [v0.2.0](https://github.com/animu-sphere/usd-gltf-plugins/releases/tag/v0.2.0)

## Objective

Open more static glTF scenes as ordinary USD: texture transforms, quantized meshes, cameras, lights,
WebP images and nine material extensions, each verified on its own, with every Khronos sample
asset recorded as opened, verified in USD meaning and rendered, separately. The
[0.2.0 changelog](../../CHANGELOG.md#020---2026-11-09) lists what ships, and the
[capability matrix](../reference/CAPABILITY_MATRIX.md) states the supported subset of each feature.

## Compatibility

- Packages target the same OpenStrata `cy2026` / `usd` runtimes as v0.1.0: Windows x86-64, Linux
  x86-64 and macOS arm64, with OpenUSD 26.08 and Python 3.13. Each works only with the exact runtime
  it was built for, as [ADR 0009](../adr/0009-release-targets.md) decides.
- Writing and editing are unsupported, and the plugin has no public C++ interface.
- Files that required an extension now implemented import instead of failing, and a rejection names
  each cause it found.

## Accepted limitations

- Animation, skins, morph targets, points and lines, sparse accessors, Draco, meshopt and the other
  unimplemented required extensions are rejected with a diagnostic. In the
  sample check, 94 of 339 files were.
- UsdPreviewSurface has no transmission, volume, specular, sheen, iridescence or anisotropy; it
  ignores them with a warning, and only the MaterialX network carries them.
- `gltf_pbr` 1.39.5 connects none of the volume inputs, so every path draws a thin material.
- Anisotropy and normal maps use a tangent frame the renderer derives, so supplied tangents and
  handedness do not control shading, and a rotated or mirrored normal map's frame does not turn
  through Storm's MaterialX path.
- Storm draws transmission as transparency without refraction, and ignores spot cones. A light's
  `range` is ignored, with a warning.
- A source inside a package such as a `.usdz` fails when it needs an image or an external buffer
  ([ADR 0025](../adr/0025-packaged-sources.md)). Other resolution through custom asset resolvers is
  not supported.
- Meshes referenced more than once are duplicated, not shared. The
  [import measurements](../reference/CAPABILITY_MATRIX.md#import-measurements) found a candidate for
  sharing, which is left to a later version.
- Display was checked only with Storm on one Windows machine. Texture filters are not applied.
- The v0.1.0 limits on [crafted PNG images](../adr/0006-image-failures.md#limits) and
  [one conversion at a time](../architecture/LAYER_AUTHORING.md#investigation) still apply.

## Verification observed

At the release candidate, `main` with fastgltf 1.0.1, before the version change, on Windows 11 with
MSVC, OpenUSD 26.08 and an NVIDIA RTX A5000, after a clean build:

- `ost test` passed 8 of 8 tests.
- The [display check](../reference/CAPABILITY_MATRIX.md#display-checks) passed 681 comparisons, none
  failing, with the lookdev runtime.
- The [sample check](../reference/CAPABILITY_MATRIX.md#sample-assets) of all 339 files at
  glTF-Sample-Assets `8f49239`, with renders, matched its baseline in opening, rejection and meaning:
  245 opened, 199 of them verified in USD meaning and 46 partly, and 94 rejected. Storm drew 244 through
  both shader paths. The seven opened files never rendered before were added to the baseline; one, the
  10000-mesh NodePerformanceTest GLB, took over 600 seconds through each path.

CI and the release workflow build, test and package on all three platforms, and fail on their own;
their runs are linked from the GitHub release.
