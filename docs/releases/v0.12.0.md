# v0.12.0 - Dispersion

- **Tag** `v0.12.0`
- **Date** 2026-11-17
- **Release** [v0.12.0](https://github.com/animu-sphere/usd-gltf-plugins/releases/tag/v0.12.0)

The importer reads `KHR_materials_dispersion` in glTF and GLB. A dispersion above 0 on a material
with a volume is authored as the MaterialX `gltf_pbr` `dispersion` input, with glTF's meaning of 20
over the Abbe number. See the [changelog](../../CHANGELOG.md#0120---2026-11-17) and the
[dispersion decision](../adr/0040-dispersion.md).

## Compatibility and limits

- Packages target the pinned OpenStrata `cy2026` / `usd` runtimes on Windows x86-64, Linux x86-64
  and macOS arm64 with OpenUSD 26.08 and Python 3.13.
- No renderer in reach draws dispersion. MaterialX 1.39.5's `gltf_pbr` does not read the input, and
  Storm draws transmission without refraction, so materials look as glTF's fallback without the
  extension. UsdPreviewSurface ignores dispersion with a warning. See the
  [material design](../design/MATERIALS.md#dispersion).
- A negative dispersion, a wrong type or a value too large for a float fails the import, even where
  the dispersion would not be authored.
- `KHR_materials_diffuse_transmission` stays unsupported: neither shader has an input for it. See
  [ADR 0039](../adr/0039-diffuse-transmission.md).

## Verification observed

On Windows x86-64 with OpenUSD 26.08, the 6 Khronos sample files that use dispersion matched the
glTF dispersion of each material, and Storm drew each of them through MaterialX and
UsdPreviewSurface. The display check rendered volume materials with dispersions of 1 and 2.04 the
same as without one. See the [sample check](../reference/CAPABILITY_MATRIX.md#sample-assets) and
[display checks](../reference/CAPABILITY_MATRIX.md#display-checks).

The [release gate](../roadmap/README.md#release-gate) repeats the checks at the commit to be
tagged. The GitHub release provides package pins and checksums.
