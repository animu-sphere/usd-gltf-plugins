# v0.1.0 - practical import of static PBR glTF

- **Tag:** `v0.1.0`
- **Commit:** `0a0bc02bb89b56e66f2127e377d65d3027022947`
- **Date:** 2026-11-02
- **Release:** [v0.1.0](https://github.com/animu-sphere/usd-gltf-plugins/releases/tag/v0.1.0)

## Objective

Open representative static and textured glTF and GLB files through `Usd.Stage.Open`, as ordinary
USD with hierarchy, bindings and both shader paths, without a custom schema or imaging plugin. The
[0.1.0 changelog](../../CHANGELOG.md#010---2026-11-02) lists what ships.

## Compatibility

- Packages target the OpenStrata `cy2026` / `usd` runtimes on Windows x86-64, Linux x86-64 and macOS
  arm64, with OpenUSD 26.08 and Python 3.13. Each works only with the exact runtime it was built
  for, as [ADR 0009](../adr/0009-release-targets.md) decides.
- Writing and editing are unsupported, and the plugin has no public C++ interface.

## Accepted limitations

- Animation, skins, morph targets, selected cameras and lights, Draco and other required extensions,
  and points and lines are rejected with a diagnostic. In the check below, 24 of 87 files were.
- `KHR_texture_transform` and texture filters are not applied.
- Display was checked only with Storm on Windows, on simple fixtures.
- A PNG crafted with valid chunks and invalid data
  [crashes OpenUSD's image loader](../adr/0006-image-failures.md#limits), with or without this plugin.
- Conversions run [one at a time](../architecture/LAYER_AUTHORING.md#investigation), which limits
  reading many files in parallel. The crash this avoids was reproduced on macOS, and its mechanism
  inside TBB was not found.
- Only Linux and macOS packages came out identical between the dry run and the tag, at the same
  source. Windows packages did not, so reproducibility is shown only within one build there.

## Verification observed

At the tag commit:

- The [tag workflow](https://github.com/animu-sphere/usd-gltf-plugins/actions/runs/41388405224), the
  [dry run](https://github.com/animu-sphere/usd-gltf-plugins/actions/runs/41387878323) and CI passed
  on all three platforms. Each built and passed 8 of 8 tests, packaged twice with one digest, and
  opened fixtures from a package extracted outside the repository.
- The [display check](../reference/CAPABILITY_MATRIX.md#display-checks) passed 395 comparisons, none
  failing, on Windows with the lookdev runtime and an NVIDIA RTX A5000.

Before the tag, on the commits it descends from:

- 63 of 87 Khronos sample files opened, and 9 rendered with nothing visibly wrong by eye. The
  [sample asset results](../reference/CAPABILITY_MATRIX.md#sample-assets) have the details. This used
  a build before the authoring thread changed.
- The test suite ran 360 times on macOS, three at a time, without a crash. The same load crashed
  about 7% of runs before the fix.
- The Linux package exported no fastgltf, simdjson or simdutf symbols.
