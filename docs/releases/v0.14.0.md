# v0.14.0 - Points and lines

- **Tag** `v0.14.0`
- **Date** 2026-11-21
- **Release** [v0.14.0](https://github.com/animu-sphere/usd-gltf-plugins/releases/tag/v0.14.0)

The importer reads `POINTS` as `UsdGeomPoints`, and `LINES`, `LINE_STRIP` and `LINE_LOOP` as linear
`UsdGeomBasisCurves`. Without NORMAL they are drawn unlit, as their base color plus their emissive
factor, as glTF recommends; with it, lit without normal textures. No Khronos sample file is now
rejected for points or lines. See the [changelog](../../CHANGELOG.md#0140---2026-11-21) and the
[points and lines decision](../adr/0042-points-and-lines.md).

## Compatibility and limits

- Packages target the pinned OpenStrata `cy2026` / `usd` runtimes on Windows x86-64, Linux x86-64
  and macOS arm64 with OpenUSD 26.08 and Python 3.13.
- glTF defines no size for points and lines. Points have the constant width 0 and curves no widths,
  so a renderer's own treatment applies: Storm draws lines one pixel wide and points on one
  multisample of a pixel, so they look dim. A renderer that draws a zero width as nothing shows no
  points. See the [scene conventions](../design/SCENE_CONVENTIONS.md#points-and-lines).
- Lit lines in Storm are shaded with a normal facing the camera, not the authored one.
- Points and lines without NORMAL are bound to `_Unlit` material variants, and with NORMAL and a normal
  texture to `_NoNormalTexture` variants. An emissive texture on unlit points and lines is left out
  with a warning. See the [material design](../design/MATERIALS.md#points-and-lines).
- Morph targets, skins and Draco compression on points and lines fail with a diagnostic.
- The archived `KHR_materials_pbrSpecularGlossiness` and the unratified `KHR_meshopt_compression`
  are still rejected.

## Verification observed

On Windows x86-64 with OpenUSD 26.08, both MeshPrimitiveModes files and PrimitiveModeNormalsTest
open, agree with values decoded from the glTF, and draw through MaterialX and UsdPreviewSurface in
Storm. Of the 339 sample files, 334 open and 5 are rejected, each for a cause it has. See the
[sample check](../reference/CAPABILITY_MATRIX.md#sample-assets). The
[display check](../reference/CAPABILITY_MATRIX.md#display-checks) passed 837 comparisons, including
points and lines in darkness and under a light.

The [release gate](../roadmap/README.md#release-gate) repeats the checks at the commit to be
tagged. The GitHub release provides package pins and checksums.
