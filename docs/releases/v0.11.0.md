# v0.11.0 - Material variants

- **Tag** `v0.11.0`
- **Date** 2026-11-16
- **Release** [v0.11.0](https://github.com/animu-sphere/usd-gltf-plugins/releases/tag/v0.11.0)

The importer reads `KHR_materials_variants` in glTF and GLB. Use `materialVariant` on `/Root` to
switch the selected scene's materials independently of animation. `Original` restores the source
bindings, and primitives without a mapping for the selected variant keep their original material.
See the [changelog](../../CHANGELOG.md#0110---2026-11-16).

## Compatibility and limits

- Packages target the pinned OpenStrata `cy2026` / `usd` runtimes on Windows x86-64, Linux x86-64
  and macOS arm64 with OpenUSD 26.08 and Python 3.13.
- Every alternate material used in the selected scene is validated on open. Invalid mappings fail
  without replacing the existing layer on reload. Choose `Original` to restore the original
  bindings. An unknown or blocked USD selection leaves mapped primitives without those opinions.
  See the [material design](../design/MATERIALS.md#material-variants).

## Verification observed

On Windows x86-64 with OpenUSD 26.08, all 21 Khronos sample files that use material variants
matched the glTF choice names, bindings and sidedness. Storm rendered the switch between
`Original` and `beach` on the MaterialsVariantsShoe GLB through MaterialX and UsdPreviewSurface.
See the [sample check](../reference/CAPABILITY_MATRIX.md#sample-assets) and
[display checks](../reference/CAPABILITY_MATRIX.md#display-checks).

The [release gate](../roadmap/README.md#release-gate) repeats the checks at the commit to be
tagged. The GitHub release provides package pins and checksums.
