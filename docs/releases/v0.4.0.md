# v0.4.0 - optimization and developer tools

- **Tag** `v0.4.0`
- **Date** 2026-11-12
- **Release** [v0.4.0](https://github.com/animu-sphere/usd-gltf-plugins/releases/tag/v0.4.0)

The packaging command converts a local glTF or GLB scene to a standalone USDZ with its images and
animation variants. The importer reuses successful KTX2 and WebP conversions within a resolver
cache scope and validates more malformed GLB, buffer, accessor and KTX2 inputs. See the
[changelog](../../CHANGELOG.md#040---2026-11-12) for the changes.

## Compatibility and limits

- Packages target the pinned OpenStrata `cy2026` / `usd` runtimes on Windows x86-64, Linux x86-64
  and macOS arm64 with OpenUSD 26.08 and Python 3.13. The file format imports read-only.
- Creating a derived USDZ requires the glTF plugin. The result opens in regular OpenUSD after
  moving it away from the glTF and its images. The
  [packaging contract](../architecture/IMPORT_PIPELINE.md#derived-usdz) covers accepted sources,
  asset paths and failure behavior.
- Reuse is scoped and subject to the [cache budget](../design/TEXTURES.md#cache-and-asset-lifetime).
  The [capability matrix](../reference/CAPABILITY_MATRIX.md) records the supported glTF subset.

## Verification observed

On Windows x86-64 with OpenUSD 26.08, the packaging tests reopened derived USDZ files with the glTF
plugin and source files removed. The [scoped image reuse measurements](../reference/CAPABILITY_MATRIX.md#scoped-image-reuse)
compare both image read passes with the baseline on the same five assets. The
[mesh sharing experiment](../reference/CAPABILITY_MATRIX.md#mesh-sharing-experiment) recorded no
measurable benefit on the test asset, so the release uses authored meshes at each placement.

The [release gate](../roadmap/README.md#release-gate) repeats the display and sample checks at the
commit to be tagged. The GitHub release links the packaging run and provides package pins and
checksums.
